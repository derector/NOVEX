# NOVEX Motion Studio — полное ТЗ и рабочий контракт

Версия документа: 1.1  
Статус: единый рабочий документ для продолжения разработки  
Репозиторий: https://github.com/derector/NOVEX  
Основные источники требований: `MASTERSKILL.md`, `ANGSKILL.md`, `docs/NOVEX-ROADMAP.md`, `README-NOVEX.md`, текущий интерфейс и решения пользователя в переписке.

> Это ТЗ описывает целевое поведение продукта, а не утверждает, что все функции уже реализованы. Фактический статус каждой функции подтверждается исходным кодом, сборкой и проверкой работающего приложения.

## 1. Продукт и цель

NOVEX Motion Studio — локально-ориентированная студия для создания музыкальных и motion-видео по визуальным референсам. **Разрешены только две поставки: Web/PWA и Android APK. Отдельная программа для ПК не входит в продукт и не должна разрабатываться.** Продукт должен иметь две поставки из одного согласованного исходного кода:

1. Веб-приложение, устанавливаемое как PWA и публикуемое через GitHub Pages.
2. Android-приложение в виде устанавливаемого APK на Capacitor.

Ключевой результат — не только монтажный план или превью, а скачиваемый MP4 с корректным видео, графикой, таймингом и звуком. Проект должен продолжать развиваться в репозитории `derector/NOVEX`; сайт и APK собираются GitHub Actions. Источник истины для статуса сборок — реальные логи и артефакты Actions.

## 2. Принципы продукта — обязательные требования

- **Слова пользователя выше пресетов.** Явные указания «точно так же», «один в один», «скопируй» имеют приоритет над режимом, который мог бы ослабить сходство.
- **Не менять исходный монтаж без разрешения.** Не удалять паузы, повторы, дубли, не переставлять и не кадрировать исходные фрагменты. Перемонтаж — только по прямому запросу.
- **Не выдумывать отсутствующий контент.** Аутро, реплики и титры не добавлять, если пользователь не предоставил их или явно не попросил создать.
- **Формат сохраняется по умолчанию.** Ориентация, пропорции и fps должны соответствовать исходнику/заданным требованиям; изменение — только по явному указанию.
- **Лицо не обрезается.** Для видео с человеком голова должна целиком оставаться в видимой области; целевой запас — не менее 6% высоты головы со всех сторон. Если композиция референса этому мешает, адаптировать окно/масштаб, а не обрезать голову.
- **Не маскировать ограничения.** Оценочные таймкоды, процедурная графика и ограниченное сходство не называть точным распознаванием или пиксельной копией.
- **Local-first.** Исходные пользовательские медиа обрабатываются на устройстве и не отправляются на сервер без отдельного, понятного согласия. В интерфейсе честно описать любые сетевые запросы, например загрузку движка/шрифтов.
- **Сначала безопасный черновик, затем финальный рендер.** Не запускать дорогой рендер без проверки входов и плана.
- **Не заявлять о готовности без доказательств.** Нужны статус CI, артефакт и проверки ключевого пользовательского сценария.

## 3. Платформы и доставка

### 3.1 Веб/PWA
- Адаптивный веб-интерфейс для телефонов, планшетов и браузеров; это веб-сайт/PWA, а не отдельная desktop-программа.
- Публикация из ветки `main` в GitHub Pages через Actions.
- Корректные Vite base path и абсолютные пути ресурсов при размещении в подкаталоге GitHub Pages.
- Манифест, иконка, установка на главный экран и service worker.
- Кэширование оболочки приложения без устаревшего кода после обновления; сетевые ресурсы и FFmpeg должны иметь понятную стратегию cache/update.
- Проверить живой URL сайта в браузере, навигацию и загрузку FFmpeg WASM, не ограничиваться зелёной сборкой.

### 3.2 Android APK
- Capacitor Android, application id `studio.novex.motion`, имя `NOVEX Motion Studio` (если не изменено явно).
- CI на Node.js 22 и Java 17, установка Android SDK, синхронизация Capacitor, сборка debug APK.
- Артефакт `NOVEX-Android-APK` с файлом `app-debug.apk`.
- Проверить реальную установку/запуск, выбор видео и аудио, разрешения, память, экспорт, системное сохранение/Share.
- Не считать debug APK релизным подписанным приложением. Подготовка release signing и публикация в магазине — отдельный этап.
- Сохранение экспорта должно работать на Android: предпочтительно MediaStore/совместимый путь; системный Share — дополнительный путь, а не единственный способ получить файл.

### 3.3 GitHub Actions
- Рабочий процесс находится в `.github/workflows/` в корне репозитория.
- Отдельные задания web, deploy и android; понятные тайм-ауты и артефакты.
- Проверять реальный итог каждого задания, логи упавшего шага и наличие ожидаемых файлов.
- Не смешивать содержимое корневой старой/прототипной версии и актуальное приложение `novex-app/`: установить канонический source of truth и удалить/объяснить дублирование только после сравнения.
- Зафиксировать зависимости lock-файлом и перейти с `npm install` на `npm ci`, когда lock-файл актуален.
- Сборка должна проверять наличие FFmpeg JS/WASM файлов и APK; отсутствие ожидаемого файла означает failure.

## 4. Основной пользовательский сценарий

1. Создать новый проект.
2. Добавить одно или несколько видео-референсов; дополнительно добавить исходное видео, аудио/музыкальный трек, текст песни, реплики/аутро при наличии.
3. Просмотреть имя, длительность, разрешение, fps, ориентацию и состояние декодирования каждого файла.
4. Проанализировать видео (кадры, палитра, темп смены сцен, композиция, движение) и аудио (длительность, каналы, энергия/пики, оценочный BPM).
5. Выбрать режим работы, соотношение сторон/разрешение только в пределах указаний пользователя.
6. Сформировать монтажный/анимационный план с таймкодами, сценами, текстом, переходами и источником каждого решения.
7. Проверить и вручную поправить план и таймкоды, включая субтитры.
8. Посмотреть превью с синхронизированным звуком.
9. Запустить черновой рендер, проверить его, затем финальный экспорт.
10. Получить MP4, сохранить/поделиться им; настройки проекта и манифест входных материалов сохраняются для возобновления. Исходные большие видео не следует незаметно сериализовать в localStorage.
11. Открыть ранее сохранённый проект и восстановить настройки; пользователь должен быть предупреждён, если исходные медиа нужно выбрать повторно.

## 5. Режимы режиссуры

### A. Графика поверх пользовательского видео
- Сохранять исходную последовательность, длительность, паузы и кадрирование, кроме явно запрошенных изменений.
- Добавлять титры, субтитры, плашки, графические элементы и окна/маски по согласованному плану.
- Следить, чтобы лицо не было обрезано в каждой сцене и на переходах.
- Оригинальный звук смешивать только по настройке пользователя, с контролируемой громкостью.

### B. Копия референса
- Если сказано «один в один», переносить все типы сцен, вставки, композицию, порядок, масштаб, тайминг, кривые движения, входы/выходы и визуальную иерархию насколько это технически возможно.
- Составлять таблицу сцен и измерять позиции в относительных координатах кадра, размеры текста, продолжительность и переходы.
- Не заменять требуемые фото/видео-вставки плоскими карточками или иконками. Для внешних ресурсов хранить происхождение и лицензию; если обязательный материал недоступен, сообщить об этом явно.
- Подбирать шрифты с кириллицей и документировать ближайшее соответствие.
- До финала сверять ключевые кадры и движение с референсом. Если пиксельная копия невозможна, явно описать разницу, а не обещать абсолютное совпадение.

### C. Ролик с нуля
- Создавать процедурную анимацию из идеи/текста/музыки с выбором визуального направления.
- Направления, уже обозначенные в проекте: kinetic neon, editorial grid, liquid forms.
- Сцены, текст, длительности и акценты должны быть редактируемыми; не выдавать процедурную 3D-графику за фотогенерацию или сложную органическую анимацию видеомодели.

## 6. Референсы и анализ

- Несколько видео, drag-and-drop, список файлов с миниатюрой, длительностью, размером и удалением.
- Поддерживаемые контейнеры/кодеки проверять по фактической возможности декодирования; для неподдерживаемого HEVC — понятное сообщение и проверенный fallback, если он есть.
- Извлекать разрешение, aspect ratio, duration, fps, кадры/contact sheet, цветовую палитру, точки смены сцен и приблизительную интенсивность движения.
- Из аудио извлекать длительность, каналы, форму волны, энергетические пики и ориентировочный BPM; помечать оценки как оценки.
- Сохранять исходные факты отдельно от выводов модели/эвристики.
- Библиотека референсов должна поддерживать превью, метаданные, теги, связь с проектом и поиск.
- Не включать пользовательские референсы в публичный bundle приложения по умолчанию.

## 7. Текст, субтитры и синхронизация

- Поддерживать текст песни, отдельные реплики/текст исходного видео и опциональное аутро.
- Автоматическое распределение слов по длине текста и длительности допустимо только как черновая оценка; пользователь должен видеть возможность правки таймкодов.
- Целевая улучшенная функция — выравнивание речи/слов по аудио (ASR/forced alignment), если движок и лицензии позволяют; до появления реальной реализации нельзя называть приблизительные таймкоды распознаванием речи.
- Настраиваемые стиль, шрифт, размер, положение, обводка/тень, фон/плашка, появление и исчезновение.
- Субтитры вшиваются в итоговый MP4, если выбрано «вшить»; должны быть видны в реальном файле, а не только в интерфейсе.
- Учитывать кириллицу, переносы, безопасные поля кадра, контраст и отсутствие наложения на важные области лица.

## 8. 3D и эффекты

- Three.js-сцена должна иметь понятный жизненный цикл и синхронизацию с таймлайном: время сцены → параметры → кадр.
- Экспорт кадров с прозрачностью должен сохранять alpha; проверять формат пикселей/кодек, premultiplication и корректность композитинга поверх исходного видео.
- Время начала/окончания эффекта и появления логотипа должно работать не только от нулевой секунды; проверить кадры до старта, в момент старта и после окончания.
- Финальный композит собирается с правильным масштабом, положением, длительностью и звуком.
- Кинетические титры, субтитры, неоновое свечение и другие команды должны менять фактические пиксели экспортируемого MP4. Одного текстового «плана правок» недостаточно.
- Каждому эффекту нужны проверка превью, экспортный эквивалент и понятная ошибка при неподдерживаемом режиме.
- Приёмка 3D — экспорт реального короткого клипа с логотипом/сценой, видимым alpha-композитингом и корректным таймингом, воспроизводимого в обычном видеоплеере.

## 9. Таймлайн и превью

- Показ последовательности клипов, аудиодорожки и текстовых/эффектных слоёв.
- Переходы без непреднамеренных скачков, чёрных кадров, внезапного исчезновения элементов и рассинхронизации.
- Контролы воспроизведения, время, seek bar, превью выбранной сцены.
- Формат предпросмотра подстраивается под исходник: горизонтальный, квадратный, вертикальный. Не принуждать каждый исходник к 9:16.
- Превью должно максимально соответствовать финальному рендеру; явно маркировать функции, которые ещё не отражены в превью или экспорте.

## 10. Экспорт MP4

- Выход: MP4 с H.264/AAC для широкой совместимости; корректный faststart, частота кадров, размеры чётные и пропорции соблюдены.
- Видео и аудио должны иметь согласованную длительность, правильный старт/offset, громкость и обработку отсутствующей аудиодорожки.
- Сохранять выбранный участок/длительность и порядок сегментов; не повторять/зацикливать исходник неожиданно.
- Для overlays — композитинг по таймкодам; для титров — реальное вшивание кадров/фильтров; для 3D — alpha-композитинг.
- FFmpeg WebAssembly должен быть локально упакован/загружен с корректными путями и версиями. Показывать прогресс, этап, осмысленные логи и дружелюбные ошибки.
- Обрабатывать отмену/повтор, отсутствие памяти, неподдерживаемый кодек, не загруженный движок и невалидные файлы.
- Проверять выходной файл: ненулевой размер, MIME, длительность, возможность воспроизведения, видео- и аудиопотоки. Нельзя объявлять экспорт успешным только потому, что функция FFmpeg вернула без исключения.
- Ограничения памяти и производительности мобильного браузера документировать; для больших файлов давать понятное предупреждение.

## 11. Проекты и медиатека

- Создание, переименование/открытие и удаление черновика с подтверждением при удалении.
- Сохранять настройки, режим, таймлайн, таймкоды, параметры формата, манифест файлов и отчёт проверки.
- Поскольку Blob/URL файлов нельзя надёжно сохранять в localStorage, отделить метаданные проекта от бинарных исходников и сообщать, если медиа надо выбрать заново.
- Медиатека показывает видео, аудио и экспорт с метаданными и понятными действиями.
- Поиск и возобновление проектов — приоритет после надёжного рендера.

## 12. UX и визуальная система

- Сохранять текущую тёмную визуальную систему NOVEX: глубокий почти чёрный фон, фиолетовый акцент, панели с тонкой границей, выразительная типографика, аккуратная моушн-студийная эстетика.
- Русский интерфейс — основной; тексты ошибок и статусы понятны пользователю без технических знаний.
- В правом верхнем углу обязателен заметный пункт «Профиль» с иконкой пользователя. По нажатию открывается единое меню регистрации по email, входа по паролю, входа по email-ссылке, статуса облачной настройки и выхода из аккаунта.
- Аватар/иконка NOVEX должны быть едиными и узнаваемыми в фавиконе, PWA и интерфейсе; профильная кнопка имеет отдельный контрастный аватар и не маскируется под облачный статус.
- Во время рендера показывать фактический прогресс от 0 до 100%, текущий этап, процент готовности и процент оставшейся работы. Заполнение плавно меняет цвет от красного через оранжевый/жёлтый к зелёному. Прогресс не должен изображать завершение, если рендер завершился ошибкой.
- Мобильная адаптация обязательна: панели, таймлайн, файлы, кнопки и превью должны работать на узком экране без горизонтального переполнения.
- Доступность: видимый focus, подписи полей, контраст, доступные интерактивные элементы, статусы процесса.
- Не показывать фальшивые индикаторы готовности. Разделять «план создан», «рендер выполняется», «файл создан», «файл проверен».

## 13. Безопасность, приватность, лицензии

- Не отправлять локальные медиа на сервер без явного согласия и объяснения.
- Не встраивать секреты в клиентский bundle; Supabase publishable key допустим только при корректных RLS-политиках и настройках.
- Не хранить приватные токены в репозитории.
- Внешние шрифты/CDN и FFmpeg-ресурсы документировать; предпочтительно фиксировать версии и иметь проверку загрузки.
- Для найденных/использованных изображений сохранять источник и лицензионную информацию; соблюдать приватность пользовательских материалов.
- Не добавлять аналитические/серверные загрузки скрытно.

## 14. Критерии приёмки (Definition of Done)

### CI и доставка
- [ ] Последний commit собирает веб без ошибок; артефакт `NOVEX-Web-Build` присутствует.
- [ ] GitHub Pages deploy успешен, сайт реально открывается по опубликованному URL.
- [ ] Веб/PWA и APK остаются единственными целевыми поставками; отдельная desktop-программа не создаётся.
- [ ] В правом верхнем углу есть профиль; проверены состояния гостя, регистрация email, вход, подтверждение email, сброс пароля с последующим вводом нового пароля/вход по ссылке, выход и понятное сообщение при ненастроенном Supabase.
- [ ] Прогресс рендера показывает «готово» и «осталось», имеет плавный градиент красный→зелёный и отражает ошибки без ложного 100%.
- [ ] Android job успешен; артефакт `NOVEX-Android-APK` содержит ненулевой `app-debug.apk`.
- [ ] APK устанавливается и запускается на устройстве/эмуляторе.
- [ ] Версии исходника, commit SHA и артефакты сборки прослеживаются.

### Редактор
- [ ] Видео/аудио можно выбрать, просмотреть и проанализировать; ошибки декодирования понятны.
- [ ] Сохраняются выбранные режим, параметры, тексты и таймкоды.
- [ ] Превью правильно работает с горизонтальным, квадратным и вертикальным видео.
- [ ] Музыка синхронизирована, выбранный фрагмент соблюдается, аутро не добавляется без основания.
- [ ] Каждый включённый эффект виден в экспортированном MP4.

## 15. Приоритеты разработки

**P0 — надёжная сборка и единый исходник**
1. Установить каноническую версию приложения: корневой `index.html` и `novex-app/` сейчас содержат разные структуры; сверить историю/архив источника и не вносить исправления в неактивную копию.
2. Дождаться и подтвердить текущую Android-сборку; проверить APK artifact.
3. Проверить реальный GitHub Pages URL, base path, FFmpeg файлы и запуск.
4. Добавить lockfile/синтаксические и smoke-проверки.

**P1 — корректность экспорта**
1. Создать минимальные тестовые входы: короткий горизонтальный клип, вертикальный клип, аудио и PNG overlay.
2. Проверить загрузку FFmpeg, выходные streams, duration, sync, H.264/AAC и скачивание.
3. Исправить выявленные ошибки, добавить отчёт рендера и проверку итогового MP4.

**P2 — эффекты и 3D**
1. Проверить 3D-рендер и привязку к времени на реальном экспорте.
2. Сделать кинетические титры, субтитры и неон реальными экспортными эффектами.
3. Сравнить превью и экспорт; добавить тесты тайминга и alpha.

**P3 — UX и профиль**
1. Обновлённая иконка NOVEX и отдельная профильная кнопка в правом верхнем углу.
2. Регистрация и вход по email через Supabase; проверить, что production-сборка получила необходимые Variables и что redirect URL/SMTP настроены.
3. Понятный красно-зелёный прогресс рендера с процентами «готово/осталось».

**P4 — удобство и проекты**
1. Надёжное сохранение/восстановление проекта и манифеста медиа.
2. Медиатека и поиск референсов с источниками.

## 16. Обязательный формат отчёта о работе

Каждый отчёт должен включать:
- что проверено непосредственно;
- что изменено и commit SHA;
- какие Actions jobs завершились и с каким conclusion;
- ссылки на web build/APK artifacts;
- что реально протестировано в браузере/на устройстве;
- какие ограничения/ошибки остаются;
- следующий конкретный шаг.

Нельзя называть «готовым» то, что только скомпилировалось. «Сборка прошла», «артефакт создан», «сайт открылся», «экспорт проверен» и «APK установлен на устройстве» — разные статусы.


## 17. Дополнение ТЗ от пользователя — 2026-10-23

Это обязательные уточнения, действующие для всех следующих изменений:

1. **Только Web/PWA и Android APK.** Не собирать отдельную desktop-программу и не тратить на неё время.
2. **Полная проверка до выдачи результата.** После каждого изменения проверить синтаксис, тесты, web build, Pages deploy, Android APK build и артефакт. Отдельно указывать то, что CI не может доказать: регистрацию в реальной конфигурации, запуск на физическом Android и фактический MP4-рендер.
3. **Визуальная готовность.** Индикатор экспорта должен плавно идти от красного к зелёному, показывать процент готовности и процент оставшейся работы, этап и понятное сообщение об ошибке.
4. **Профиль.** Справа вверху обязательна иконка профиля. Она открывает меню регистрации/входа по электронной почте, входа по ссылке и выхода. Облачные функции разрешены только при настроенном Supabase и безопасных RLS-политиках; если настройки отсутствуют, интерфейс должен объяснить, что именно не настроено, не изображая успешную регистрацию.
5. **Обновление визуальной системы.** Улучшать иконки, аватар, плавность переходов, адаптивность и состояния интерфейса, не ухудшая доступность, производительность Android и поддержку reduced motion.
6. **Честная сдача.** Финальный ответ должен содержать URL сайта, ссылку на скачивание APK-артефакта, SHA коммита, итоговые статусы Actions и список сценариев, которые действительно проверены. Не называть физическую установку или реальный экспорт проверенными, если они проверялись только статическими тестами/CI.
